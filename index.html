Dispensary & AI Technology Directory

Explore official software documentation behind cannabis inventory, track-and-trace, AI and digital identity. These are research references only; Matcha Manita has no verified live vendor integrations or payment connectivity.

How dispensary API authentication works

POSaBIT v3: Integrator and venue tokens are combined for HTTP Basic authentication. Older v1/v2 endpoints use bearer tokens. Official POSaBIT authentication ↗

Treez: Integrators sign short-lived JWT requests using a protected RSA private key and registered public certificate. Treez documents a 30-second JWT lifetime. Official Treez authentication ↗

Matcha Manita status: These methods are studied only. No partner keys, credentials, live inventory sync, payments or licensed delivery fulfillment are enabled.

Newly verified: OAuth, ecommerce APIs & Codex

Cova: Public API documentation lists an OAuth2 token endpoint and data services for product, stock, pricing and tax information. Cova developer documentation ↗

Sweed: Documents a headless ecommerce API for storefront catalog and retail workflows. Access, fulfillment and payment capabilities require provider authorization. Sweed ecommerce API ↗

OpenAI Codex: The official SDK supports server-side engineering automation; it is not a public client-side API-key integration. Codex SDK documentation ↗

Digital assets: Blockchain technology research remains separate from cannabis ordering and payments. No wallets or transfers are enabled.

Engineering classroom: API keys, scopes & callbacks

Dutchie: Permission-scoped keys control access to inventory, customers and reporting. A vendor-issued key must be stored on an authorized backend, never in website JavaScript. Official API reference ↗

POSaBIT: Authorized order integrations can poll REST status endpoints or receive status callbacks. Callback receivers must validate requests and prevent duplicate processing before use. Official webhook guide ↗

Cova: Documents incremental product data updates; production integrations should avoid repeatedly requesting full inventories. Official API docs ↗

Architecture rule: Browser → approved backend → provider API. Keep secrets server-side; log only non-sensitive metadata. No live order, payment, cannabis fulfillment or blockchain transfer is enabled.

API engineering lesson: endpoints use different credentials

POSaBIT menu feed: The documented JSON catalog feed uses a feed key and Bearer API token. General POSaBIT v3 API endpoints document integrator-plus-venue HTTP Basic authentication. Always verify each endpoint's authentication method; never paste provider tokens into browser code. Menu feed documentation ↗

AI software agents: OpenAI's Agents SDK describes tool orchestration, guardrails, human review and tracing. For a dispensary website, any future agent must run server-side, use approved data only, and require human review for consequential actions. Official Agents SDK ↗
